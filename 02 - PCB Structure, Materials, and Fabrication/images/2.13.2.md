## Suggested Content for Figure 2.13.2

**Figure title for authoring/reference only:**  
`Gerber-Based File Set versus Intelligent PCB Manufacturing Data Exchange`

### Instructional Purpose

Help MET readers distinguish two ways that PCB manufacturing intent may be packaged for transfer to a fabricator:

1. a **coordinated Gerber-based file set with supporting data**; and
2. a **structured intelligent manufacturing-data exchange**, such as IPC-2581.

The figure appears in Section 2.13.6 and should clarify the information-packaging concept without turning the section into a file-format tutorial.

### Central Teaching Message

> **Gerber-based exchange and intelligent structured exchange package manufacturing information differently, but either workflow must communicate a complete, internally consistent definition that the intended fabricator can interpret correctly.**

The figure must **not** imply:

- Gerber = obsolete or invalid;
- intelligent data exchange = automatically correct;
- one format eliminates the need for engineering control;
- one format alone contains every product requirement in every company's workflow.

The layout should make the internal relationships look machine-readable/structured without becoming a software schema diagram.

`Fabricator / CAM`

### Required Technical Relationships

The figure must communicate these points:

1. A Gerber-based workflow normally uses multiple coordinated layer-oriented files plus supporting manufacturing information.
2. Gerber-based manufacturing exchange can be complete and reliable when the **whole release package** is controlled and consistent.
3. Modern Gerber files may carry useful attributes; the figure must not portray Gerber as nothing more than anonymous bitmaps.
4. Structured intelligent exchange can preserve machine-readable relationships among geometry, construction, materials, drilling, connectivity, and manufacturing/test information.
5. IPC-2581 is shown only as an **example** of intelligent structured exchange.
6. Both methods still require:
   - complete information;
   - internal consistency;
   - revision control;
   - support by the intended fabricator.
7. Both methods feed the same manufacturing objective: the intended bare PCB.

Do not imply that structured exchange eliminates drawings, contractual requirements, purchasing requirements, supplier review, or engineering judgment.

### Spatial / Geometry Requirements

- Use two columns of equal width and comparable visual weight.
- Keep the left side from looking cluttered with dozens of tiny file icons.
- Use 5–6 simplified file tiles at most; combine closely related information where appropriate.
- On the right, use one structured container with 5–6 clearly labeled internal fields.
- Use equal arrows from both columns to `Fabricator / CAM`.
- Do not use red/green success/failure styling.
- Keep the shared criterion `Complete + consistent + supported by supplier` centered and readable.
- Ensure `Example: IPC-2581` is visually subordinate to the general term `Structured intelligent data exchange`.
- Do not place a "better" arrow or progression arrow from Gerber to IPC-2581; this is a comparison, not a historical migration sequence.

### Color / Style Guidance

Follow the established EPAC figure language:

- explicit white background;
- clean flat engineering diagram;
- restrained navy/charcoal text;
- pale cool color family for the Gerber-based side;
- a different but equally restrained pale neutral/accent family for the structured side;
- identical line weights and typography on both sides;
- no glossy file icons;
- no 3D database cylinder unless extremely simplified;
- no decorative binary code, circuit patterns, or software-screen motifs;
- no "old vs new" color coding.

Color must not carry the distinction alone; column headings and structural layout must make the comparison understandable in grayscale.
