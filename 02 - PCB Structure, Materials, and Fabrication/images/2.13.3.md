## Suggested Content for Figure 2.13.3

**Figure title for authoring/reference only:**  
`From Engineering Release to Verified Bare PCB`

### Instructional Purpose

Show the complete **information-and-verification loop** that connects engineering release to a fabricated and verified bare PCB.

This figure supports Sections 2.13.8–2.13.11. Its purpose is not to re-teach the detailed PCB fabrication sequence from Section 2.8. Instead, it should show where supplier review, engineering resolution, fabrication, verification, and quality evidence fit around that fabrication activity.

### Central Teaching Message

> **PCB manufacturing is a controlled loop: engineering releases the board definition, the supplier reviews it, questions are resolved before uncontrolled changes occur, the board is fabricated, and conformance is evaluated against the released requirements using appropriate verification methods and objective evidence.**

The visual should make two concepts unmistakable:

1. supplier/CAM review can **loop back to engineering before fabrication**; and
2. verification methods and records are tied to **controlled requirements**, not performed as disconnected paperwork.

### Overall Layout

Use a clean **left-to-right primary flow** with one clearly separated feedback loop.

Recommended main flow:

`Controlled engineering release`
→
`Supplier capability / CAM review`
→
`Fabrication`
→
`Verification`
→
`Quality evidence`
→
`Verified bare PCB`

Below or above `Supplier capability / CAM review`, include a feedback branch:

`Question / conflict / capability concern`
→
`Engineering resolution`

From `Engineering resolution`, return to the controlled review path with one of three concise outcomes represented as subordinate labels:

- `Clarification`
- `Authorized deviation`
- `Design change / updated release`

The return arrow should lead back to the controlled release/review path before fabrication.

Inside the `Verification` box, use short subordinate labels:

- `Electrical`
- `Visual / dimensional`
- `Coupon / microsection when required`

Inside the `Quality evidence` box, use short subordinate labels such as:

- `Inspection / test records`
- `Traceability / conformance records`

The main flow should remain simple and readable.

### Required Technical Relationships

The figure must show these relationships correctly:

1. The starting point is a **controlled engineering release**, not an informal CAD file.
2. Supplier capability/CAM review occurs before or as part of production preparation.
3. A supplier question or conflict does not go directly to an uncontrolled shop-floor workaround.
4. Questions/concerns return to engineering for documented resolution.
5. Resolution may be:
   - clarification of existing intent;
   - authorized deviation;
   - design change with updated controlled release.
6. If the controlled product definition changes, the flow returns through the controlled release/review path before fabrication.
7. Fabrication is a high-level single box here because Section 2.8 already teaches the detailed fabrication sequence.
8. Verification evaluates the finished board against applicable released requirements.
9. Verification can include:
   - electrical checks;
   - visual/dimensional checks;
   - coupon/microsection evaluation when required.
10. Quality evidence consists of records tied to those requirements and verification activities.
11. The endpoint `Verified bare PCB` means that conformance has been evaluated according to the applicable requirements; it does not imply every board uses every possible inspection method.
12. The figure must not imply that a certificate of conformance by itself replaces required inspection/test evidence.

### Spatial / Geometry Requirements

- Main flow should read clearly from left to right.
- Use one consistent arrow style for the primary flow.
- The feedback loop should use a distinct route/position but not rely on color alone.
- Avoid crossing the feedback loop through the fabrication or verification boxes.
- Keep `Engineering resolution` close enough to the review box that the loop is easy to follow.
- Subordinate labels inside boxes should be smaller than main box labels but still readable at 900 px.
- The `Verified bare PCB` endpoint may use a simplified bare-board silhouette/check symbol, but the text label must carry the meaning.
- Avoid large factory, clipboard, or certificate illustrations; the logic is more important than decorative icons.
- Keep all objects inside safe margins.
- Use enough vertical separation that the feedback loop does not collide with the main sequence.

### Color / Style Guidance

Follow established EPAC figure style:

- explicit white background;
- restrained flat engineering diagram;
- dark navy/charcoal text and lines;
- pale neutral/blue-gray main flow boxes;
- feedback loop may use a secondary restrained accent;
- verification/evidence boxes may use a subtle different fill but should remain visually consistent;
- no red/green pass/fail coding as the primary meaning;
- no gradients or shadows unless extremely subtle;
- consistent sans-serif typography;
- medium-weight arrows with clear arrowheads;
- no corporate workflow/poster style.

Color must not be essential to understanding the loop.
