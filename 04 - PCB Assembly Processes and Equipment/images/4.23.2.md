# Figure 4.23.2 Suggested Content - NPI Build Readiness Loop from Released Revision to Controlled Production

## Status

**Suggested-content specification - Rev1 QA-reviewed candidate**

This file defines the instructional content and generation constraints for Figure 4.23.2 in Section 4.23, **NPI and Manufacturing Job Package Basics**.

The figure has one instructional role: **show NPI as an iterative manufacturing-readiness loop from released product revision through preparation, staged build/setup verification, controlled correction, and authorization to proceed**.

Do **not** call this specification or generated artwork canonical/final before explicit project-owner acceptance.

---

## Figure Title for Authoring / Reference Only

**NPI Build Readiness Loop from Released Revision to Controlled Production**

Do **not** place this overall title or figure number inside the artwork.

---

## Instructional Purpose

Show that NPI is not simply a one-way handoff from design to production.

The figure should connect:

- released product revision;
- manufacturing-data review;
- job-package/program preparation;
- material/tooling/equipment readiness;
- an initial/prototype/pilot/staged build as applicable;
- first-board/setup verification;
- a decision on whether the required checks are satisfied;
- controlled correction or engineering change when they are not;
- authorization to proceed to the next production stage when they are.

The figure should allow a beginning MET reader to answer:

> **What happens when a new or revised PCB assembly job is not yet ready to proceed?**

---

## Central Teaching Message

> **NPI turns a released product revision into a controlled manufacturing job through readiness preparation, build/setup verification, controlled correction when needed, and authorization to proceed.**

A secondary message should remain visually clear:

> **If an issue changes controlled information, update the affected source/output and recheck readiness before continuing.**

## Overall Layout

Use a **left-to-right main readiness path** with one explicit lower feedback loop.

Recommended main path:

`Released product revision`
→
`Manufacturing-data review`
→
`Job package + programs prepared`
→
`Material / tooling / equipment readiness`
→
`Initial / staged build as applicable`
→
`First-board / setup verification`
→
decision:
`Required checks satisfied?`

From the decision:

- **YES** → `Proceed to next authorized production stage`
- **NO / issue found** → `Controlled correction / engineering change`

Then:

`Update affected controlled information / outputs`
→
return to `Manufacturing-data review` or a clearly labeled `Readiness review` point.

The return path must clearly re-enter the controlled review process. It must not shortcut directly back into production.

### Build-stage wording

Use a compact main label such as:

- `Initial / staged build`

Optional secondary line:

- `prototype / pilot as applicable`

This wording must not imply that prototype, pilot, and first article are three universal mandatory sequential stages.

## Required Technical Relationships

1. The process must begin from a **released product revision**, not an uncontrolled draft.
2. Manufacturing-data review must occur before the job is treated as factory-ready.
3. Job-package/program preparation must occur before the initial/staged build.
4. Material/tooling/equipment readiness must be established before the build proceeds.
5. The build stage must be qualified as **as applicable**; do not imply that prototype and pilot are mandatory separate steps for every organization.
6. First-board/setup verification must occur before the authorization branch.
7. The decision must have an explicit success path and explicit issue path.
8. The **YES** path must go to `next authorized production stage`, not automatically to `full production`.
9. The **NO / issue found** path must go to controlled correction/change work.
10. A correction that affects controlled information must update the affected source/output before readiness is rechecked.
11. The feedback loop must return to review/readiness rather than bypass verification.
12. The figure must not show an undocumented shop-floor workaround as an acceptable path.
13. The figure must not imply that first-board/setup verification is universally equivalent to a formal regulated-industry First Article Inspection.
14. The figure must not imply that prototype success automatically qualifies the production process.
15. The figure must not expand into detailed Section 4.25 startup/changeover execution; it should remain at the NPI/readiness concept level.
16. The figure must not show Chapter 5 nonconformance/MRB/CAPA systems.

## Spatial / Geometry Requirements

- Use a clear left-to-right main path.
- Place `Released product revision` at the far left.
- Keep the main preparation/build/verification sequence aligned on one horizontal band.
- Place the decision diamond/block near the right side.
- Place the successful authorization block to the right or upper-right of the decision.
- Place the correction/update path below the main sequence.
- Route the feedback arrow leftward beneath the main path and return it to `Manufacturing-data review` or a clearly labeled `Readiness review` point.
- Do not return the feedback line directly to the build box.
- Avoid crossed arrows.
- Keep `YES` and `NO / issue found` labels close to their respective outgoing branches.
- Use no more than two or three lines of text in each main process box.
- Keep all text horizontal.
- Use approximately **5-7% outer margins** and comfortable internal padding.
- Ensure the decision text remains readable at 900 px.
- Arrows/leaders must not pass through text or icons.
