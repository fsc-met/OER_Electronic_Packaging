# Figure 4.25.1 Suggested Content - Changeover Readiness Across the PCB Assembly Line

## Status

**Suggested-content specification - Rev1 QA-reviewed candidate**

This file defines the instructional content and generation constraints for Figure 4.25.1 in Section 4.25, **Changeover, First-Board Verification, and Production Readiness**.

The figure has one instructional role: **show that changeover readiness is a cross-line configuration-agreement problem, not a collection of independent machine-ready states**.

Do **not** call this specification or generated artwork canonical/final before explicit project-owner acceptance.

---

## Figure Title for Authoring / Reference Only

**Changeover Readiness Across the PCB Assembly Line**

Do **not** place this overall title or figure number inside the artwork.

---

## Instructional Purpose

Show how the active product/job configuration must remain consistent across the physical board, board side/orientation, materials, paste, stencil/tooling, printer setup, placement setup, and reflow setup before the line is allowed to process the first board.

Students should understand why a line can contain several machines that individually report "ready" while the **overall line is still wrong for the active job**.

The figure should connect the controlled product/revision context from Section 4.23 and the verified material context from Section 4.24 to the equipment/process setup already taught in Sections 4.8, 4.13, and 4.15.

It should also reinforce that a mismatch at any required setup point produces a **hold -> correct -> reverify** condition before the first-board gate.

---

## Central Teaching Message

> **The line is ready for the first board only when the active job, physical board/side, materials, tooling, and machine programs or recipes all agree with the same approved product configuration.**

A secondary message should remain visually clear:

> **Machine-ready is not the same as line-ready.**

Program/recipe identifiers do not have to use the same revision label as the product, but each must be controlled and traceably linked to the applicable product configuration.

## Overall Layout

Use a **cross-line readiness diagram** with one controlling configuration band, one main left-to-right setup path, and one clearly separated mismatch/hold branch.

Recommended structure:

### Top controlling band

`Active job / product / revision / side / route`

This band should visually feed or govern all downstream setup groups.

### Main readiness path

`Physical PCB / panel`
→
`Materials + solder paste`
→
`Stencil / tooling + printer setup`
→
`Placement setup: program + feeders + nozzles`
→
`Reflow setup: recipe + applicable profile evidence`
→
`Ready for first board`

A small precondition near the left may show:

`Previous-job items removed or positively segregated`

Use this as a restrained supporting cue, not a full process stage.

### Mismatch branch

Any required setup mismatch should route to:

`STOP / HOLD`
→
`Correct controlled input / setup`
→
`Reverify`
→
return to the affected setup check

The mismatch branch must remain visually separate from the normal ready-for-first-board path.

The figure should represent the **whole PCB assembly line** at readiness level. It should not redraw printer, feeder, pick-and-place, or oven internals.

## Required Technical Relationships

1. The **active job/product configuration** is the controlling reference for the entire line.
2. The physical PCB/panel must agree with the active product, revision, side/pass, and intended orientation.
3. Previous-job boards, materials, tooling, labels, or programs must not remain active in a way that can enter the new job accidentally.
4. Component materials and solder paste must be verified for the current job before first-board processing.
5. The stencil/tooling and printer program/recipe must correspond to the current board/product configuration.
6. The placement program, feeder/material assignments, nozzles/tools, board support, and alignment references must correspond to the active job.
7. The reflow oven must use the intended product recipe and be in the required ready/stable condition before processing the first board.
8. The figure must distinguish the **oven recipe** from the **applicable product/profile verification evidence**.
9. Program or recipe revision labels do not need to equal the product revision label; the figure should imply controlled linkage rather than identical numbering.
10. A machine reporting ready does not prove that its loaded setup is correct for the active product.
11. A line is not `Ready for first board` until all required setup groups agree with the same active product configuration.
12. Any unresolved mismatch in product/revision, board/side, materials, tooling, program, feeder/nozzle, orientation, or reflow setup routes to a hold/correct/reverify condition.
13. The hold/correction path returns to the affected verification point; it must not jump directly to the ready-for-first-board state.
14. The figure must not imply that a first-board pass has already occurred; Figure 4.25.1 ends **before** first-board processing begins.
15. The figure must not imply that the readiness checks shown establish long-term process capability.
16. The figure must remain a generic engineering-readiness model, not a manufacturer-specific operating procedure.

## Spatial / Geometry Requirements

- Use a strong left-to-right main flow.
- Place the active-job/product-configuration block above the main line so its controlling relationship is obvious.
- If control lines descend from the top band, use short clean connectors that terminate at the relevant setup group without crossing unrelated labels.
- Keep the physical-board group near the left side.
- Keep materials/paste adjacent to board/setup context but visibly separate from the PCB.
- Keep printing, placement, and reflow groups in process order.
- Place `Ready for first board` at the far right.
- Place the mismatch/hold branch below the main process band.
- Route mismatch arrows downward from the relevant verification region, then toward one common `STOP / HOLD` region where practical.
- A correction/reverify arrow may return toward the affected setup group, but it must not cross the normal main-path labels.
- Keep all text horizontal.
- Use no more than two or three lines in a main setup box.
- Use comfortable internal padding.
- Keep station/group widths visually balanced but allow a wider placement group if needed.
- Use approximately **5-7% outer margins**.
- Do not let equipment icons dominate the setup labels.
- Do not place feeder/material icons so close that they look like one physical object.
- Arrowheads must terminate cleanly at box edges or gate symbols.
- No arrow or leader may run through unrelated text.
- The entire composition must remain readable at 900 px.

Important qualifications to preserve:

- company changeover/line-clearance procedures vary;
- some setups use barcode/software verification and others use controlled manual checks or combinations;
- program/recipe identifiers need controlled linkage, not identical revision labels;
- profile-verification triggers vary with product, process, equipment, and local procedure;
- the line-ready gate precedes first-board processing and is not equivalent to production release.

Use sources to verify engineering relationships only. Do not copy or trace vendor setup screens, textbook figures, equipment manuals, or factory workflow graphics.
