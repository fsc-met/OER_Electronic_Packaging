# Figure 4.24.1 Suggested Content - From Approved Part Requirement to Correct Feeder Loading

## Status

**Suggested-content specification - Rev1 QA-reviewed candidate**

This file defines the instructional content and generation constraints for Figure 4.24.1 in Section 4.24, **Material Kitting and Line-Side Verification**.

The figure has one instructional role: **show the wrong-part-prevention identity chain from the approved job requirement to the physical component container, feeder assignment, and active placement job**.

Do **not** call this specification or generated artwork canonical/final before explicit project-owner acceptance.

---

## Figure Title for Authoring / Reference Only

**From Approved Part Requirement to Correct Feeder Loading**

Do **not** place this overall title or figure number inside the artwork.

---

## Instructional Purpose

Show why correct material loading requires more than recognizing a reel, tray, or tube by appearance.

The figure should connect the controlled product requirement to the physical material and then to the exact line-side location expected by the active placement job. It should help students see that a component can be the correct approved part and still create a wrong setup if it is associated with the wrong feeder or feeder location.

The figure should also make one important limitation visible: barcode/2D scanning or another automated check can compare identities against controlled information, but it does not create engineering approval for an alternate part.

---

## Central Teaching Message

> **Correct loading requires agreement among the approved job requirement, the physical component identity, the feeder/location assignment, and the active placement job.**

A secondary message should remain visually clear:

> **Scanning verifies identity against controlled data; it does not create approval.**

Any unresolved mismatch should lead to a hold/reverify condition rather than continued loading.

## Overall Layout

Use a **left-to-right controlled identity-chain diagram** with one main verification path and one clearly separated mismatch/hold branch.

Recommended main path:

`Approved job requirement`
→
`Approved part identity`
→
`Physical reel / tray / tube`
→
`Scan / controlled verification`
→
`Assigned feeder + location`
↔
`Active placement job / expected feeder map`
→
`Loading verified`

A lower conditional branch should show:

`Mismatch at any required check`
→
`STOP / HOLD`
→
`Resolve identity / authorization / feeder mapping`
→
`Reverify before loading`

The active placement job should function as a **comparison reference** for the feeder/location relationship rather than appearing as a physical material object.

The figure should not look like a detailed pick-and-place machine anatomy diagram. Its unique role is **material identity and feeder-mapping control**.

## Required Objects and Labels

### 1. Approved job requirement

Required main label:

- `Approved job requirement`

Required representative information:

- `Product / revision`
- `Internal part number`
- `Approved MPN / alternate`

Recommended visual:

- a generic controlled BOM/job-record/document symbol;
- concise data fields rather than a realistic software screen.

Do not imply that the line operator creates or approves alternates.

### 2. Approved part identity

Required label:

- `Approved part identity`

Required relationship:

- internal part number maps to one or more **already approved** manufacturer part numbers where the controlled product definition allows it.

Recommended concise sublabel:

- `Internal PN -> approved MPN(s)`

Do not show an unapproved visually similar substitute as acceptable.

### 3. Physical component container

Show one generic **reel** as the primary example because the sequence ends at feeder loading. A small secondary tray/tube cue may be included only if it remains uncluttered.

Required label:

- `Physical reel / tray / tube`

Required representative label fields on or beside the container:

- `MPN`
- `Internal PN` where applied by the factory
- `Lot / batch`
- `Quantity`
- `Barcode / 2D code`

Optional small status cue:

- `Handling / moisture status where applicable`

Do not recreate a real supplier label or proprietary barcode format.

### 4. Scan / controlled verification

Required label:

- `Scan / controlled verification`

Required comparison cues:

- `job requirement`
- `container identity`
- `feeder identity / location`

Optional small qualifier:

- `manual / scanner / software check as applicable`

This qualifier is useful if space permits because the project must not imply that every factory has the same automated interlock architecture.

### 5. Assigned feeder and location

Required labels:

- `Assigned feeder`
- `Feeder ID`
- `Slot / location`

A representative identifier such as `F12` may be used only if marked or visually treated as an **example**, because actual factories use different feeder/slot naming conventions.

Use a generic tape-feeder representation. Do not reproduce a vendor-specific feeder model.

### 6. Active placement job / feeder map

Required labels:

- `Active placement job`
- `Expected part-to-feeder map`

Recommended visual:

- a generic job/program/data symbol adjacent to the feeder block;
- comparison line(s) between expected and actual feeder/material assignment.

The figure should make clear that the active job expects a specific approved part identity at a specific feeder/location.

### 7. Successful verification state

Required label:

- `Loading verified`

Optional supporting note:

- `part + feeder + active job agree`

Use a restrained check/enable symbol.

Do not label this as final product acceptance, incoming inspection acceptance, or process qualification.

### 8. Mismatch / hold branch

Required labels:

- `Mismatch at any required check`
- `STOP / HOLD`
- `Resolve and reverify before loading`

Use a restrained amber/red-orange warning or hold box.

Do not show an operator selecting a substitute, overriding the system, or continuing production without controlled resolution.

## Required Technical Relationships

1. The **approved job requirement** is the controlling source for what component is allowed for the active product/revision.
2. Internal part number and manufacturer part number must remain visibly distinct concepts.
3. An internal part number may map to one or more approved MPNs only when the released/controlled product information permits that choice.
4. The physical reel/tray/tube must be identified and matched to the controlled requirement.
5. A visually similar component must not be shown as acceptable merely because package size, value marking, or appearance looks similar.
6. Barcode/2D scanning must be shown as an **identity-verification method**, not the source of engineering approval.
7. The assigned feeder identity/location must be verified in addition to the component-container identity.
8. The active placement job/program must expect the same part-to-feeder relationship.
9. A correct approved reel in the wrong feeder location must be shown as a mismatch condition.
10. A feeder/location that was valid for a different job/revision must still be a mismatch for the current active job.
11. `Loading verified` occurs only after the relevant identities agree for the active job/revision and feeder assignment.
12. Any unresolved mismatch in part identity, approval status, feeder identity/location, or active-job mapping routes to `STOP / HOLD` and re-verification.
13. Alternate/substitute approval must exist **before** line-side verification; the figure must not imply that scanning or an operator can create approval.
14. Lot/date code and handling/moisture fields may appear as identity/status information, but the figure must not turn them into universal acceptance thresholds.
15. The figure must not imply that every factory uses barcode automation. The underlying verification logic may be implemented by controlled manual checks, scanner/software interlocks, or a combination.
16. The figure must preserve the Section 4.24 rule that **correct material + correct identity + correct location + correct job** must agree before normal loading proceeds.

## Spatial / Geometry Requirements

- Maintain a strong left-to-right reading direction.
- Keep the main identity-chain stages on one horizontal visual band where practical.
- Place the approved job requirement at the far left and visually upstream of all physical material/load steps.
- Keep the physical container large enough to show a simplified label without crowding.
- Place the scan/verification stage between the physical container and feeder assignment.
- Position the active placement job/expected feeder map close enough to the feeder block that their comparison relationship is obvious.
- Use a double-ended or paired comparison relationship only where it is visually clear; do not make the active-job block look like another physical process step.
- Place the mismatch/hold branch below the main chain.
- Route mismatch branches from the verification/feeder/job comparison region without crossing the main flow.
- If a reverify arrow is shown, route it back to the verification stage, not directly to `Loading verified`.
- Keep all text horizontal.
- Use no more than two or three lines in a main process box.
- Preserve approximately **5% outer margins** and comfortable internal padding.
- No arrowhead should touch a border, label, barcode symbol, or feeder object.
- Avoid dense callout leaders around the container label.
- The full figure must remain readable at 900 px without zooming.
