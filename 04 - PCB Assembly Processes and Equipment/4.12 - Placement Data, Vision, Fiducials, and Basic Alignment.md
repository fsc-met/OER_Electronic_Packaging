# 4.12 - Placement Data, Vision, Fiducials, and Basic Alignment

Section 4.11 followed one component through a pick-and-place machine. The next question is how the machine knows **where** that component belongs on the actual PCB inside the machine.

The answer combines two kinds of information:

> **placement data describe the intended component locations; vision and fiducials relate those intended locations to the actual board and the actual picked component.**

This section introduces only the data and alignment ideas needed to understand that relationship. Detailed setup, changeover, and troubleshooting are developed in Section 4.13.

---

## 4.12.1 - What Placement Data Must Tell the Machine

A placement job needs enough information to identify each component location and its intended orientation. Common CAD exports are often called **centroid files**, **component placement lists (CPLs)**, **pick-and-place files**, or **XY/XYR files**.

A basic placement record commonly includes:

- **reference designator** - the component instance on the schematic/PCB, such as `R12`, `C7`, or `U3`;
- **X coordinate** - the horizontal position of the component's defined placement origin;
- **Y coordinate** - the perpendicular horizontal position;
- **rotation** - the intended angular orientation;
- **board side** - top or bottom;
- **package or component-library identifier** - information used to associate the placement record with the correct physical package and machine handling definition.

The name **centroid file** is common, but the X/Y value is useful only when the CAD placement origin, package/library definition, units, rotation convention, and machine import convention agree.

> **A correct coordinate with the wrong origin or rotation convention is still a wrong placement instruction.**

---

## 4.12.2 - Read a Representative Placement-Data Table

Table 4.12.1 is a small illustrative example. The values are not tied to one CAD tool or machine.

| Ref. | Package / library key | X (mm) | Y (mm) | Rotation | Side |
|---|---|---:|---:|---:|---|
| R12 | R0603 | 18.50 | 12.00 | 0° | Top |
| C7 | C0402 | 22.15 | 12.00 | 90° | Top |
| U3 | SOIC-8 | 40.80 | 26.35 | 180° | Top |
| Q2 | SOT-23 | 55.10 | 32.40 | 90° | Bottom |

This table tells the placement software **which component instance**, **where**, **how rotated**, and **which side**. It does **not** by itself define every machine setting. The production job may also associate the component with a feeder location, nozzle, recognition method, package dimensions, and other machine-library data. Exact pickup/placement parameters are machine- and process-specific and are not implied by the simple table.

The exact column names vary. Rotation-zero definitions, positive rotation direction, units, and bottom-side mirroring conventions can also vary between CAD exports and machine software. Those conventions must be verified during program preparation rather than assumed.

---

## 4.12.3 - Coordinate Origin, X/Y Position, Rotation, and Board Side

X and Y coordinates need a defined **coordinate origin**. Depending on the design and manufacturing workflow, the origin may be a board corner, a CAD auxiliary origin, a panel reference, or another defined datum.

Rotation is measured about the component's placement axis, but **0° is not a universal physical direction independent of the library**. The footprint/library definition establishes the reference orientation, and the export/import workflow determines how that orientation is represented.

Bottom-side placement needs extra care because CAD/export and machine software can use different viewing and mirroring conventions. The import workflow must intentionally map the bottom-side coordinates and rotation; students should not assume that one vendor's numeric convention transfers unchanged to another.

A beginning technologist does not need to memorize every CAD system's convention. The important habit is to verify:

1. **Where is the placement origin?**
2. **What units are being used?**
3. **What direction is positive rotation?**
4. **What does 0° mean for this package/library record?**
5. **How does this workflow represent the bottom side?**

## 4.12.4 - Placement Data and the Component Library Work Together

The placement-data file says where a component instance belongs. The machine's component or package library provides information needed to physically handle and recognize that type of component.

Depending on the machine, library data may include items such as:

- body length and width;
- component height;
- expected lead, ball, or body geometry;
- recognition method;
- usable nozzle or pickup-tool choices;
- pickup/reference point;
- orientation definition.

This gives one important distinction:

> **`U3` identifies a component instance; the package/library record describes how that physical component is recognized and handled.**

A placement file can therefore contain reasonable-looking coordinates and still fail if the imported package orientation or library definition is inconsistent with the CAD data.

This section does not teach component-library creation. The goal is simply to recognize that **placement coordinates and component definitions must agree**.

---

## 4.12.5 - Why Fiducials Are Needed

Mechanical stops, conveyor rails, and clamps bring the PCB close to the intended machine position. They do not guarantee that every board enters at exactly the same X/Y position and angle.

A **fiducial** is a deliberately provided machine-readable reference mark on the PCB or panel. The board-recognition camera locates programmed fiducials and compares their measured positions with the expected positions.

From those measurements, the placement system can establish board-position corrections such as:

- X translation;
- Y translation;
- in-plane rotation;
- on systems that support it, scale or other geometric compensation.

The key idea is:

> **The placement file describes an ideal board. Fiducial recognition tells the machine how the real board in front of it differs from that ideal reference.**

Two widely separated board-level fiducials are a common arrangement because their separation gives the vision system information about board position and angular orientation. Some systems use additional marks to support scale/distortion checks, panel alignment, redundancy, or local registration. Exact fiducial count and correction model are machine- and process-dependent.

---

## 4.12.6 - Global and Local Fiducials

Two useful terms are:

- **global fiducials** - board- or panel-level reference marks used to align the overall placement coordinate system;
- **local fiducials** - reference marks near a particular component or local region, often used when tighter local registration is useful for fine-pitch or otherwise demanding placement.

Local fiducials do not replace the overall board reference. When the process/equipment supports them, they provide an additional nearby registration reference for a component or local region.

Not every product uses the same fiducial strategy. Fiducial count, location, geometry, clearance, and recognition method are design- and process-dependent.

## 4.12.7 - Basic Board Shift and Rotation Correction

Suppose a component has a programmed placement center of

$$
(X,Y)=(42.00,\ 18.50)\text{ mm}
$$

and board recognition shows a pure translation of

$$
\Delta X=+0.18\text{ mm}, \qquad \Delta Y=-0.12\text{ mm}
$$

with negligible rotation.

For this simple translation-only example,

$$
X_{\text{corrected}}=42.00+0.18=42.18\text{ mm}
$$

and

$$
Y_{\text{corrected}}=18.50-0.12=18.38\text{ mm}
$$

The machine would therefore target approximately

$$
(42.18,\ 18.38)\text{ mm}
$$

for that component under this simplified condition.

If the board is also rotated, adding the same X/Y shift to every component is not enough. The controller applies a coordinate transformation so placement locations follow the actual board orientation.

A small angular error can matter over a large board. For an illustrative rotation of $0.20^\circ$ about a reference point,

$$
\theta = 0.20^\circ\left(\frac{\pi}{180^\circ}\right)\approx 0.00349\text{ rad}
$$

At a point $100\text{ mm}$ from that reference, the approximate tangential displacement is

$$
s\approx r\theta=(100\text{ mm})(0.00349)\approx 0.35\text{ mm}
$$

This is an **illustrative geometry example, not a machine tolerance**. It shows why a board can look nearly straight to the eye and still require optical alignment before fine placement.

## 4.12.8 - Board Alignment and Component Alignment Are Different Corrections

Section 4.11 introduced two vision functions. They solve different problems.

| Vision function | What is measured | Why it matters |
|---|---|---|
| **board recognition** | fiducial/reference positions on the PCB | establishes where the actual board is relative to the programmed board coordinates |
| **component recognition** | picked component position and orientation relative to the head/nozzle | establishes pickup X/Y/$\theta$ offset before final placement |

The controller uses both kinds of information, but they belong to different coordinate relationships. Conceptually:

> **programmed target -> transform to the actual board -> compensate the measured pickup offset -> placement motion**

This is a useful way to think about the process, but it is not a machine-programming formula. Different placement systems implement their coordinate transforms and vision corrections differently.

## 4.12.9 - Practical Checks Before the First Board

Before accepting a new or changed placement program, a beginning technologist should be able to verify the following with the approved setup procedure:

1. **Correct file/job?** The loaded placement job matches the intended PCB revision and assembly side.
2. **Units correct?** Millimeters and inches have not been confused.
3. **Origin correct?** The imported coordinate origin matches the job setup.
4. **Rotation convention correct?** A few easy-to-recognize polarized or asymmetric parts have the expected orientation.
5. **Board side correct?** Top and bottom placements appear on the intended side with the expected transformation.
6. **Package/library mapping reasonable?** The component record is linked to the intended package/library definition.
7. **Fiducials recognized?** The machine finds the expected board references without an abnormal recognition result.
8. **Board map reasonable?** A graphical preview or first-board check shows components over the intended footprints rather than shifted, mirrored, or rotated as a group.

A useful first diagnostic pattern is:

> **If many components are shifted or rotated in a common pattern, first investigate the board/job coordinate and alignment chain. If one reference or one component type is wrong while the rest of the board is correct, investigate that component's data, source, library, pickup, orientation, or local setup before changing a global correction.**

The detailed first-board, setup, changeover, and placement-problem workflow continues in Section 4.13.

---

## Section Takeaway

The main ideas from this section are:

- placement data commonly identify a reference designator, X/Y location, rotation, board side, and package/library association;
- the coordinate origin, units, rotation convention, and board-side interpretation must agree across CAD export and machine import;
- the placement file describes intended locations, while the component library tells the machine how a package is physically recognized and handled;
- global fiducials establish the board-level reference, while local fiducials can provide additional nearby alignment information when used;
- board vision corrects the relationship between the ideal coordinate set and the actual PCB position;
- component vision measures pickup position/orientation so the placement motion can compensate for the part's actual position on the nozzle;
- a small board rotation can create a meaningful position error far from the reference point;
- the correct response to an alignment problem is to follow the evidence, not to change several offsets or machine parameters at once.

Section 4.13 brings these ideas together during **placement setup, changeover, first-board verification, and common placement-problem troubleshooting**.
