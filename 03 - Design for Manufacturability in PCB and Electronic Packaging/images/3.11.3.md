## Suggested Content for Figure 3.11.3

### Figure title for authoring/reference only

`Electrical Node and Physical Test Access`

### Instructional purpose

Teach the difference between **electrical connectivity** and **physical test access**.

The figure should show that a required electrical node can exist correctly in the circuit/layout while still being difficult or impossible to contact with a probe after assembly.

It should also show that an intentionally accessible connector contact can be another valid test-access path when it exposes the required signal.

### Central teaching message

> **A net is not automatically testable just because it exists electrically. Probe-based testing needs an exposed, reachable conductive target or another intentional access method.**

### Canonical PNG filename

`3.11.3 - Electrical Node and Physical Test Access.png`

### Intended mdBook display width

`900 px`

### Recommended canvas size / aspect ratio

- Authoring canvas: approximately `1800 x 1000 px`.
- Recommended aspect ratio: approximately `16:9` to `9:5`.
- Three compact top-view scenarios are recommended.

### Overall layout

Use a **three-panel top-view comparison**:

1. `Accessible test point`
2. `Blocked target`
3. `Connector access`

Use a consistent PCB visual language across all panels.

The first two panels should use the **same net name and trace topology** where practical so the difference between electrical connection and physical reachability is unmistakable.

### Required objects and labels

#### Panel 1 — Accessible test point

Show:

- PCB trace/net;
- exposed conductive test point labeled `TP1`;
- probe tip approaching from above;
- label `Reachable conductive target`;
- optional check mark.

#### Panel 2 — Blocked target

Show:

- the same or clearly equivalent net;
- an exposed pad or intended target electrically connected to that net;
- a component body, connector body, or shield obstructing probe approach;
- probe tip stopped/deflected before contact;
- label `Blocked probe path`;
- optional X mark.

Do not simply cover the target with solder mask in this panel; the main lesson should be **physical obstruction**, not a solder-mask rule.

#### Panel 3 — Connector access

Show:

- installed generic connector;
- accessible connector pin/contact tied to the required signal;
- test lead/probe entering the connector or mating with the exposed contact;
- label `Intentional connector access`.

### Required technical relationships

- The accessible test point must be a real exposed conductive feature.
- The probe tip in the good panel must physically contact or clearly be able to contact the target.
- The blocked panel must retain an unbroken electrical trace to the target while the physical probe approach is obstructed by installed hardware.
- Do not imply that a blocked node is electrically disconnected.
- The connector panel must show an accessible contact that actually exposes the intended signal.
- Do not imply every connector is automatically a suitable test interface.
- Do not draw the probe through opaque component/shield geometry.
- Do not assign universal test-point diameter, probe pitch, or keep-out dimensions.
- Do not turn the figure into an ICT fixture or flying-probe machine diagram.

### Spatial / geometry requirements

- Use the same board orientation and visual scale across panels.
- Make electrical connectivity visible with a consistent trace/net line.
- Place the probe tip far enough from labels to avoid clutter.
- In the blocked panel, the obstruction must clearly sit in the probe approach path.
- Keep `TP1`, blocked target, and connector contact large enough to remain visible at 900 px.
- Use simple arrows/leaders only when needed.
- If a net highlight is used, combine color with a label such as `Required node` so meaning is not color-dependent.


### Color / style guidance

- Clean engineering-textbook appearance consistent with current EPAC figures.
- White or very light neutral background.
- Flat 2D schematic geometry or restrained cross-section drawing; no photorealism.
- Restrained engineering palette:
  - green/blue-green PCB or solder-mask field;
  - copper/gold conductive features;
  - dark gray component bodies;
  - muted blue/gray inspection or probe geometry;
  - limited red only for a blocked/problem condition when needed.
- Sans-serif labels with enough size for the 900 px mdBook render.
- Consistent line weights and moderate visual hierarchy.
- No decorative gradients, dramatic shadows, glossy rendering, logos, or watermarks.
- Do not rely on color alone; use labels, line style, geometry, symbols, and/or check/X cues.
- Do not embed the external figure number, final caption, or an oversized overall title inside the artwork.


### Scope boundaries

This figure should **not** teach:

- ICT fixture construction;
- bed-of-nails probe counts;
- flying-probe axis/robot mechanisms;
- universal test-point dimensions;
- detailed boundary-scan architecture;
- functional-test sequence;
- electrical measurement theory;
- rework access.

ICT, flying probe, connector-based test, and boundary scan are explained in prose/tables at awareness level. This figure owns only the **electrical node versus physical access** relationship.

### Technical-verification basis

Use as technical grounding:

- current Section 3.11.3 and 3.11.4 text;
- approved Chapter 3 outline requiring test points, probe access, connector access, ICT awareness, flying-probe awareness, and boundary-scan awareness;
- Keysight ICT information confirming physical probe/test-point access;
- Seica flying-probe information confirming movable probes still require reachable conductive targets;
- Section 3.10 distinction between test-point **labeling** and actual test-point **physical access**;
- Coombs/Blackwell design-for-test/testability context.

No universal numerical test-point geometry should appear in this figure.

### Originality / copyright requirements

Create an original generic PCB/probe-access schematic.

Do not:

- copy an ICT fixture diagram;
- trace a flying-probe machine image;
- reuse a manufacturer's test-point graphic;
- reproduce a textbook testability figure;
- use recognizable commercial connector geometry or logos.

The board, traces, probe tip, and connector should be generic and independently drawn.

### Editable SVG requirements

The strongest final candidate should include a publication PNG and a **true editable SVG**.

The SVG must:

- use vector geometry rather than an embedded raster image as the primary artwork;
- keep text editable where practical;
- keep board features, component bodies, package cross-sections, rays, arrows, probe tips, leaders, labels, and symbols as separate editable objects;
- define explicit `width`, `height`, and `viewBox` values;
- use `preserveAspectRatio="xMidYMid meet"`;
- include an explicit full-canvas white rectangle as the first visible drawing element;
- preserve adequate outer margins so no label, ray, leader, or arrow is clipped;
- use `markerUnits="userSpaceOnUse"` for normal engineering arrows unless there is a specific technical reason not to;
- remain readable when rendered at native size and approximately 1600 px, 1200 px, and 900 px width.

Before recommendation, render-check the final SVG at all four sizes.
