## Suggested Content for Figure 3.15.1

### Figure title for authoring/reference only

`Applied DFM Review Map Across a PCB Assembly`

### Instructional purpose

Provide one visual index to the six functional review categories used by Section 3.15:

1. Fabrication
2. Assembly
3. Inspection / Test
4. Rework / Service
5. Tooling / Handling
6. Release

The figure should help a student understand that the checklist is not six unrelated lists. Five categories act on the same physical PCB/PCBA/panel, while the release category checks the controlled information and review state associated with that same design.

### Central teaching message

> **One PCB assembly must satisfy several manufacturing functions before release.**

The figure should visually reinforce:

> **Fabrication, assembly, inspection/test, rework/service, and tooling/handling review the same physical design; release confirms that the checks, findings, and controlled data agree.**

### Canonical PNG filename

`3.15.1 - Applied DFM Review Map Across a PCB Assembly.png`

### Intended mdBook display width

`900 px`

### Recommended canvas size / aspect ratio

- Authoring canvas: approximately `1800 x 1100 px`.
- Recommended aspect ratio: approximately `16:10`.
- The layout should remain legible when reduced to `900 px` width.

### Overall layout

Use one central simplified PCB assembly in a light panel/handling context.

Arrange five physical review-category callouts around the central design:

- upper left: `Fabrication`
- upper center/right: `Assembly`
- right: `Inspection / Test`
- lower right: `Rework / Service`
- lower left: `Tooling / Handling`

Place a distinct `Release` block below the physical design rather than pointing it at one physical feature. The release block should be connected to the **overall reviewed design**, not to a single board feature.

Recommended composition:

- one central green PCB assembly only;
- one light gray temporary panel/rail boundary around that same PCB;
- one or two optical fiducial/tooling features on the rail;
- one THT hole/via region;
- one short copper-trace region;
- one fine-pitch or polarized component;
- one visible test point;
- one component with a simple local rework-access envelope;
- one connector or edge component;
- five concise physical callout boxes with leaders terminating on appropriate features;
- one separate release-data block containing short release-review terms.

The figure should read as a **review map**, not as a chronological manufacturing process.

### Required objects and labels

#### Central physical design

Required generic objects:

- PCB outline;
- temporary panel/handling rail or panel frame;
- several generic SMD components;
- one polarized/fine-pitch component with a simple orientation cue;
- representative copper trace/pad region;
- representative plated hole or via;
- visible test point;
- connector or edge-related component;
- global/panel fiducial;
- tooling/alignment hole;
- one local rework-access or tool-approach envelope.

Do not attempt to make the board electrically functional. It is a teaching schematic.

#### Review-category labels

Required category labels:

- `Fabrication`
- `Assembly`
- `Inspection / Test`
- `Rework / Service`
- `Tooling / Handling`
- `Release`

Recommended concise secondary terms:

**Fabrication**
- `Copper / holes / mask`

**Assembly**
- `Footprint / spacing / orientation`

**Inspection / Test**
- `Visibility / test access`

**Rework / Service**
- `Tool / removal access`

**Tooling / Handling**
- `Rails / fiducials / support`

**Release**
- `Checks completed`
- `Findings resolved`
- `Revision consistency`
- `Release package ready`

These are summary states only; do not draw the detailed Section 3.14 finding-disposition or revision-mismatch workflows.

Optional central label:

- `Same PCB assembly / panel`

### Required technical relationships

- `Fabrication` leader(s) must terminate on bare-board geometry such as copper, holes/vias, mask, or board-edge geometry.
- `Assembly` leader(s) must terminate on component/footprint/placement features rather than on the release-data block.
- `Inspection / Test` must point to an actual visible inspection/test feature such as a solder-joint region or test point.
- `Rework / Service` must point to a component region where tool approach/removal space is visually meaningful.
- `Tooling / Handling` must point to rail/fiducial/tooling/support geometry rather than ordinary PCB copper.
- `Release` must be visually separate from the physical-feature callouts because it evaluates the controlled review/data state rather than one physical location.
- All five physical categories must visibly act on the **same** PCB/PCBA/panel rather than on six separate example boards.
- The figure must not imply that the categories are independent. The same physical feature may affect more than one category even though each callout should have one primary anchor.
- The release block should conceptually receive the reviewed design and controlled information, but it must not duplicate the detailed supplier-disposition or revision-consistency flows from Section 3.14.
- Do not encode universal numerical pass/fail dimensions in this synthesis figure.

### Spatial / geometry requirements

- Keep one dominant central PCB/PCBA/panel object.
- Keep the PCB clearly distinguishable from the temporary panel/rail material.
- Use generous margins around the central object so five callout boxes can fit without leader crossings.
- Leaders should be short, orthogonal or gently angled, and should terminate on the intended feature.
- Avoid more than one leader per review-category box unless a second anchor is essential.
- Do not place review boxes on top of the PCB.
- Keep the `Release` block below the central physical design and visually centered on the whole PCB/panel so it reads as the controlled final review state.
- Connect the release block to the overall design with at most one broad neutral connector; do not use six separate arrows converging on it.
- Keep at least one clear leader-free corridor around the central PCB so the composition does not become a spoke-wheel poster.
- If a rework-access envelope is shown, use a restrained translucent outline and avoid implying a universal clearance dimension.
- Fiducials and tooling holes must be visually distinct:
  - fiducial = surface optical target;
  - tooling hole = mechanical hole.
- If an edge component is shown, it should not automatically be shown as a DFM failure; the figure is a review map, not a good/bad comparison.

### Color / style guidance

- Clean engineering-textbook appearance consistent with the existing EPAC Chapter 3 figures.
- Explicit white background.
- Flat 2D vector/schematic style.
- Suggested restrained palette:
  - dark/mid green for PCB;
  - light gray for temporary panel/rail material;
  - gold/copper tone for fiducials/pads where useful;
  - dark gray for components;
  - muted blue/blue-gray for review callouts and leaders;
  - muted orange only for the local rework-access envelope or a review-emphasis region;
  - limited green for an eventual release-ready state if shown.
- Do not rely on color alone; every category must have a text label.
- No gradients, photorealistic PCB rendering, shadows, decorative icons, vendor logos, or software UI elements.
- No embedded external figure number or final caption.
- Do not place an oversized duplicate figure title inside the artwork.
- Do not add decorative `Pass/Review/N/A` badges around the board; the figure teaches review categories, not status coding.

### Technical-verification basis

Use as grounding:

- current Section 3.15 Rev3 QA Candidate;
- approved Section 3.15 outline;
- Sections 3.4 through 3.14;
- primary Chapter 3 `DFM Checklist & Tools` teaching sequence;
- prior Chapter 3 technical verification against current supplier practice and approved references.

Specific verified relationships represented:

- fabrication review includes copper, holes/vias, board edges, mask, and robustness;
- assembly review includes footprint, placement, spacing, orientation, and land-pattern suitability;
- inspection/test review includes optical visibility and physical probe access;
- rework/service review includes tool approach and removal/service access;
- tooling/handling review includes rails, fiducials, tooling holes, conveyor/support access, and separation context;
- release review includes configured DRC, broader DFM/DFA, supplier findings, revision consistency, and package readiness.

Important nuance:
- this is a conceptual map, not a universal process standard;
- actual governing requirements remain product-, component-, supplier-, and equipment-dependent.

### Originality / copyright requirements

Create an original educational schematic.

Do not:

- copy a PCB layout from a commercial product;
- trace an IPC figure;
- reproduce a supplier panel drawing;
- copy an AOI/test/rework illustration from a vendor;
- use a real manufacturer's release checklist graphic;
- use branded icons or software screenshots.

All PCB geometry, component shapes, panel rails, callouts, fiducials, tooling holes, document blocks, and leaders should be independently drawn.

### Generation guidance

Use a controlled technical-figure workflow.

1. Establish the complete review-map composition from this specification.
2. If AI image generation is used for the concept stage, preserve that raster concept as its own revision.
3. Once the central-board layout and callout language are promising, freeze the overall visual language.
4. Make targeted corrections only; do not redesign correct portions without a technical reason.
5. Prefer a controlled SVG/vector rebuild if labels, leader geometry, fiducial/tooling distinction, or release-block relationships cannot be controlled reliably in raster generation.
6. Verify every callout against the actual feature it names.
7. Verify that the final artwork contains exactly six review categories and that no category is accidentally duplicated or omitted.
8. Preserve every meaningful revision under a new filename.
9. Do not copy/rename a candidate to the canonical publication filename until explicit project-owner acceptance.
