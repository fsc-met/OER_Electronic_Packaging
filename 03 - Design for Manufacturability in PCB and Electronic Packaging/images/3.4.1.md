## Suggested Content for Figure 3.4.1

**Figure title for authoring/reference only:**  
`Placement Position, Rotation, and Orientation`

### Instructional purpose

Help MET readers connect **PCB placement data** to the physical location and orientation of a component on the board.

The figure should make four ideas visually obvious:

1. a pick-and-place machine follows the X-Y position supplied by the design;
2. the component center/centroid provides the placement reference;
3. rotation and polarity/pin-1 orientation are part of the placement definition;
4. accurate equipment cannot compensate for incorrect placement data or a wrong/ambiguous orientation.

This figure supports Section 3.4.1 and should prepare readers for the later placement/orientation discussion without turning into a detailed CAD-file or machine-programming diagram.

### Central teaching message

> **Pick-and-place accuracy does not replace correct design data: position, centroid, rotation, footprint, and orientation must all be defined correctly.**

A secondary visual message is:

> **Real placement has finite variation, so the design must tolerate normal deviation from the nominal position.**

### Overall layout

Use a **two-part horizontal composition**.

#### Left side — Placement data becomes physical pose

Show one simplified PCB top view containing:

- a board reference/origin;
- a component footprint;
- the component centered over the footprint;
- a centroid marker;
- X and Y location indicators;
- a rotation arrow;
- a visible pin-1 or polarity marker.

This panel explains how the digital placement description maps to the physical board.

#### Right side — Correct versus problematic placement

Use a compact side-by-side comparison:

**Preferred / clear placement**
- component centered on the intended footprint;
- orientation mark clearly matches the intended polarity/pin-1 direction;
- slight dashed "normal variation" envelope may be shown around the nominal pose.

**Problematic placement**
- component noticeably offset from the footprint center and/or rotated incorrectly;
- polarity/pin-1 direction inconsistent or ambiguous;
- use one or two concise callouts such as `Offset placement` and `Wrong / unclear orientation`.

Do not make the right side a full failure-analysis panel. It is only a placement-data interpretation check.

### Required objects and labels

#### Left placement-data panel

Required objects:

- simplified PCB outline;
- board origin/reference symbol;
- one component footprint with pads;
- one component body;
- centroid/crosshair at component center;
- X-direction indicator;
- Y-direction indicator;
- rotation arrow;
- pin-1 or polarity marker.

Required labels:

- `Board reference`
- `X position`
- `Y position`
- `Centroid`
- `Rotation`
- `Pin 1` or `Polarity` depending on the chosen generic component symbol

A small label such as `Nominal placement` is acceptable.

#### Right comparison panel

Required labels:

- `Preferred`
- `Problematic`

Preferred panel should include:

- `Centered`
- `Clear orientation`

Problematic panel should include one or both:

- `Offset`
- `Wrong / unclear orientation`

If a finite-variation envelope is shown, label it:

- `Normal placement variation`

Do not place a numerical tolerance on that envelope unless the figure specification is later deliberately revised. The current section already supplies the representative numerical scale in prose.

### Required technical relationships

The final figure must correctly show that:

1. X and Y describe the component's nominal board location.
2. Rotation defines angular orientation about the placement reference/centroid.
3. Polarity or pin-1 information is a separate design intent that must remain consistent with the component/footprint.
4. The footprint pads and component body must correspond geometrically.
5. A correctly functioning placement machine can still place a component incorrectly if the supplied centroid, rotation, footprint, or orientation data are wrong.
6. Normal placement variation should be small relative to the overall footprint and should not be drawn as a dramatic shift.
7. The figure must not imply that the machine "finds" the correct orientation independently of design/program data.
8. The figure must not imply that all components must use the same global orientation.

### Spatial / geometry requirements

- Use a true top-view PCB representation.
- Keep the component body centered over the footprint in the preferred example.
- The centroid marker must visually lie at the intended placement reference point.
- X and Y indicators should originate from or clearly reference the board coordinate system.
- The rotation arrow should curve around the centroid or component center.
- The pin-1/polarity marker must be visible and attached to a specific package corner/end.
- The problematic offset should be large enough to teach the concept but still physically plausible.
- Do not move the component so far that it no longer overlaps the pads at all; that would depict an extreme placement failure rather than the intended DFM concept.
- Keep all arrows and callouts outside text boxes where possible.
- Use at least **60 px outer margin** on the working canvas.
- Avoid crossing leader lines.

### Color / style guidance

Use the established EPAC textbook style:

- explicit white background;
- simple 2D top view;
- restrained blue/green/gray palette;
- copper/pads may use muted copper/tan;
- component body may use dark gray or muted blue;
- centroid/coordinate indicators may use a contrasting dark blue;
- use red/orange only sparingly for the problematic example;
- legible sans-serif text;
- consistent line weights;
- no photorealism;
- no decorative icons;
- no large internal overall title;
- no embedded public figure number or caption.

The figure should remain understandable in grayscale. Use position, labels, and line style—not color alone—to distinguish preferred and problematic states.

- a CAD export-file format diagram;
- a machine vision system diagram;
- a detailed feeder/nozzle illustration;
- a machine-accuracy specification chart;
- a land-pattern design tutorial;
- a component-spacing figure;
- a soldering/reflow-process figure.

Do not include:

- specific vendor machine names;
- proprietary machine data;
- detailed fiducial algorithms;
- stencil/paste information;
- board-edge spacing;
- AOI shadowing;
- tombstoning.

Those topics are handled elsewhere in Section 3.4 or later sections.
