## Suggested Content for Figure 3.12.1

### Figure title for authoring/reference only

`Rework Tool Approach and Component Removal Space`

### Instructional purpose

Show that successful rework requires more than enough room for the original component placement.

The figure should make two physical requirements visible:

1. the rework tool must have a practical approach path to the target component/joint region;
2. the component must have enough free space to be gripped and removed after the solder is released.

This figure should visually deepen the rework-access concepts introduced in Sections 3.4 and 3.5 without becoming another generic component-spacing figure.

### Central teaching message

> **A component can fit on the PCB and still be difficult to rework if the tool cannot approach or the component cannot be gripped and removed safely.**

### Canonical PNG filename

`3.12.1 - Rework Tool Approach and Component Removal Space.png`

### Intended mdBook display width

`900 px`

### Recommended canvas size / aspect ratio

- Authoring canvas: approximately `1800 x 1000 px`.
- Recommended aspect ratio: approximately `16:9` to `9:5`.
- Use enough height to show a vertical lift/removal path clearly.

### Overall layout

Use a **two-panel good-versus-poor comparison**.

Left panel:
- `Good rework access`

Right panel:
- `Restricted rework access`

Each panel should show the same generic target SMT component and a similar PCB region.

The left panel should show:
- open tool approach from at least one practical side;
- tweezers or gripping tool reaching the component;
- a clear vertical lift/removal path.

The right panel should show:
- neighboring tall/dense parts restricting the tool approach;
- gripping access blocked or severely limited;
- the removal/lift path colliding with nearby hardware.

The figure should not become a numerical spacing chart.

### Required objects and labels

Both panels should include:

- horizontal PCB surface;
- one target SMT component, preferably a medium-size IC or rectangular component that can plausibly be gripped;
- neighboring components;
- one generic soldering/rework tool approach representation, drawn so the shaft/tip relationship to the target is physically plausible;
- one gripping/tweezer representation;
- one vertical or slightly oblique component removal arrow.

Left panel labels:

- `Target component`
- `Tool approach`
- `Tweezer / grip access`
- `Clear removal path`

Right panel labels:

- `Target component`
- `Blocked tool approach`
- `Restricted grip access`
- `Removal path obstructed`
- `Tall / nearby component` where useful.

Optional:
- green check on the good panel;
- red X on the poor panel.

Do not add the numeric `0.5 / 1.0 / 2.0 mm` sequence inside the artwork; the section prose owns those planning values.

### Required technical relationships

- The tool must approach the actual target component/joint region rather than pointing vaguely at the board.
- The good-case tool path must be physically unobstructed.
- The poor-case neighboring component must genuinely intersect/constrain the tool approach **or** the gripping/removal envelope; do not rely on a decorative red X without physical interference.
- Tweezers/gripping geometry must plausibly contact opposite sides or suitable gripping surfaces of the target.
- The good-case lift arrow must clear neighboring components.
- The poor-case lift/removal arrow must visibly collide with or be blocked by taller/dense neighboring hardware.
- Do not imply that every rework operation uses the same tool or removal direction.
- Do not imply that a component must have a fixed universal clearance radius.
- The figure should teach physical access, not detailed soldering technique. If a hot-air cue is used, do not add a thermal zone here; that belongs exclusively to Figure 3.12.2.

### Spatial / geometry requirements

- Use matched panel scale and board orientation.
- Keep the target component approximately the same size and location in both panels.
- Make the neighboring obstruction the main geometric difference.
- Keep tool shafts, tweezer arms, and lift arrows large enough to remain readable at 900 px.
- Use a dashed outline or translucent path only when needed to show the intended removal envelope.
- Avoid crossing leader lines.
- Leave white space above the PCB for removal arrows and labels.
- Do not let tool graphics visually merge with the target component.


### Color / style guidance

- Clean engineering-textbook appearance consistent with the current EPAC figure set.
- White or very light neutral background.
- Flat 2D top-view, side-view, or restrained schematic/isometric geometry only where it improves physical understanding.
- Restrained engineering palette:
  - green/blue-green PCB field;
  - copper/gold pads or exposed conductive features;
  - dark gray component bodies;
  - muted blue/gray tools and motion arrows;
  - limited orange/red only for heat exposure or a blocked/problem condition.
- Sans-serif labels sized for the 900 px mdBook render.
- Moderate line weights and consistent visual hierarchy.
- No decorative gradients, glossy rendering, dramatic shadows, logos, watermarks, or branded commercial products.
- Do not rely on color alone; use geometry, labels, line style, arrows, and good/bad structure.
- Do not embed the external figure number, final caption, or an oversized duplicate overall title inside the artwork.


### Scope boundaries

This figure should **not** teach:

- soldering-iron tip selection;
- hot-air nozzle size;
- temperature or airflow settings;
- solder melting temperatures;
- detailed desoldering sequence;
- solder wick or vacuum methods;
- inspection/test access from Section 3.11;
- panel rails/fiducials/tooling holes from Section 3.13.

Figure 3.12.2 owns thermal exposure. Figure 3.12.3 owns product-service access to connectors, fasteners, and replaceable modules.

### Technical-verification basis

Use as grounding:

- current Section 3.12.1 and 3.12.3 text;
- primary Chapter 3 material stating that rework may require hot-air tools, soldering irons, tweezers, and probes;
- primary teaching point that dense placement increases adjacent-component damage risk and repair difficulty;
- Section 3.5's qualified spacing/rework discussion;
- IPC-7711/7721 rework/repair context supporting controlled access and avoidance of additional assembly damage;
- Chapter 4 only for boundary control, not process-detail duplication.

No universal numeric tool-clearance or removal-envelope dimension should appear.

### Originality / copyright requirements

Create an original generic PCB and tool-access composition.

Do not:

- copy a rework-station photograph;
- trace a lecture-slide image;
- reproduce a textbook repair diagram;
- use a recognizable commercial nozzle, soldering iron, or tweezer design;
- use manufacturer logos or branded package artwork.

The access relationships are factual; the composition must be independently authored.

Use a controlled technical-figure workflow.

1. Establish the composition from this specification.
2. If AI image generation is used for an early concept, preserve it only as a concept revision.
3. Once a promising visual baseline exists, freeze the visual language and make only targeted corrections.
4. Rebuild/refine as controlled vector artwork when exact tool paths, heat zones, removal arrows, fastener access, or text placement cannot be controlled reliably in raster generation.
5. Verify every word, arrow, leader, tool/component relationship, and access path after each meaningful revision.
6. Preserve every meaningful revision under a new filename.
7. Do not copy or rename a candidate to the canonical publication filename before explicit project-owner acceptance.



### Editable SVG requirements

The strongest final candidate should include both a publication PNG and a **true editable SVG**.

The SVG must:

- use vector geometry rather than an embedded raster image as the primary artwork;
- keep text editable where practical;
- keep PCB features, components, tools, heat zones, arrows, leaders, fasteners, and labels as separate editable objects;
- define explicit `width`, `height`, and `viewBox` values;
- use `preserveAspectRatio="xMidYMid meet"`;
- include an explicit full-canvas white rectangle as the first visible drawing element, e.g. `<rect x="0" y="0" width="100%" height="100%" fill="#ffffff"/>`;
- preserve adequate safe margins so no tool, arrow, leader, or label is clipped;
- use `markerUnits="userSpaceOnUse"` for normal engineering arrows unless a specific technical reason requires another setting;
- remain clear when rendered at native size and approximately 1600 px, 1200 px, and 900 px width.

Before recommendation, render-check the final SVG at all four sizes.
