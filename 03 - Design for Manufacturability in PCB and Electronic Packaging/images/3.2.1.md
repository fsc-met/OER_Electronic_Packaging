## Suggested Content for Figure 3.2.1

**Figure title for authoring/reference only:**  
`DFM in the PCB Design and Manufacturing Workflow`

### Instructional purpose

Show where Design for Manufacturability (DFM) fits within a **representative PCB design-to-production workflow** and make the feedback logic visually obvious.

The figure should help readers understand that:

- DFM is not a manufacturing-floor activity added after design;
- PCB layout is followed by automated design-rule checks and broader DFM/DFA review;
- supplier manufacturability knowledge should be brought into the design before production release when practical;
- a controlled prototype or pilot build can provide additional physical evidence;
- findings return to the design through controlled revision and rechecking;
- production release is a controlled gate for a defined revision, not the point at which engineering learning permanently stops.

This is the main spatial concept in Section 3.2, so the figure should carry the workflow logic without becoming a detailed product-development process chart.

### Central teaching message

> **DFM is an iterative pre-release design activity: automated checks, broader manufacturing review, supplier feedback, and prototype evidence can all drive controlled design revision before production release.**

The figure must show a **main forward development path** and a **clear feedback loop** back toward design revision.

It must not imply that the exact sequence is universal for every company or product.

## Overall layout

Use a clean **left-to-right workflow with a lower feedback loop**.

Recommended main path:

`Design intent`

→ `PCB layout`

→ `Design-rule checks (DRC)`

→ `DFM / DFA review`

→ `Supplier manufacturability feedback`

→ `Controlled prototype / pilot build`

→ `Feedback and design revision`

→ `Production release`

The main path should read clearly from left to right.

A **return feedback path** should run below the main flow and visually return supplier, review, and prototype findings toward `Feedback and design revision`, then back through the design/check/review loop before production release.

The figure should make it clear that revision is followed by rechecking rather than allowing a changed design to skip directly to release.

### Optional conceptual grouping

If helpful, use three subtle bands:

1. **Design definition**
   - Design intent
   - PCB layout

2. **Manufacturability verification**
   - Design-rule checks
   - DFM/DFA review
   - Supplier manufacturability feedback

3. **Evidence, revision, and release**
   - Controlled prototype/pilot build
   - Feedback and design revision
   - Production release

These bands are optional and should remain visually secondary.

## Required technical relationships

The final figure must correctly communicate all of the following:

1. Design intent precedes physical PCB layout.
2. PCB layout creates manufacturability consequences.
3. DRC checks encoded design rules.
4. DRC is separate from broader DFM/DFA review.
5. DFM/DFA review applies broader manufacturing judgment.
6. Supplier manufacturability feedback adds process-specific capability knowledge before production release when practical.
7. Prototype/pilot build, where used, provides physical evidence about the design-process interaction.
8. Supplier, review, and prototype findings can return to design revision.
9. A revised design is rechecked rather than moving directly to release.
10. Production release applies to a defined revision.
11. The workflow is representative and iterative, not a universal one-way company procedure.

The figure must **not** imply:

- DFM happens only once;
- supplier review always occurs at exactly one fixed point;
- every product requires the same prototype/pilot sequence;
- prototype hardware is built from uncontrolled working files;
- every prototype issue is automatically a PCB-layout defect;
- DRC approval equals supplier/manufacturing approval;
- production release eliminates all future manufacturing learning.

## Feedback-loop logic

### Main forward arrows

Use conventional left-to-right engineering arrows between adjacent stages.

### Return arrows

Use one clean lower feedback path.

Preferred topology:

- branches from `Supplier manufacturability feedback`, `Controlled prototype / pilot build`, and optionally `DFM / DFA review`;
- merge into `Feedback and design revision`;
- return toward `PCB layout` or a compact recheck loop covering `PCB layout -> Design-rule checks -> DFM/DFA review`.

The return geometry must make it visually impossible to interpret the process as:

`revision -> production release without rechecking`.

### Arrow interpretation

Use arrows only for:

- process progression;
- feedback/revision return.

Do not use decorative arrows or bidirectional arrows between every stage.
