## Suggested Content for Figure 3.12.3

### Figure title for authoring/reference only

`Service Access to Replaceable Parts and Fasteners`

### Instructional purpose

Show that product serviceability can require **hand/tool access and a physical extraction path**, not merely PCB-level solder clearance.

The figure should compare a deliberately serviceable arrangement with a crowded arrangement for three common service actions:

- gripping/disconnecting a connector;
- reaching a retention screw with a screwdriver;
- removing a replaceable module or part after fasteners are released.

### Central teaching message

> **If a part is intended to be disconnected, fastened, adjusted, or replaced, the layout must provide access for the hand/tool and a real removal path.**

### Canonical PNG filename

`3.12.3 - Service Access to Replaceable Parts and Fasteners.png`

### Intended mdBook display width

`900 px`

### Recommended canvas size / aspect ratio

- Authoring canvas: approximately `1800 x 1050 px`.
- Recommended aspect ratio: approximately `12:7` to `16:9`.
- A matched good-versus-poor service-layout comparison is recommended.

### Overall layout

Use a **two-panel top-view or restrained isometric comparison**.

Left panel:
- `Service access provided`

Right panel:
- `Service access restricted`

Both panels should contain the same basic service features:

1. a generic connector;
2. one replaceable module/part;
3. one retention screw or fastener.

Left panel should show:
- open finger/grip area around the connector;
- straight screwdriver approach to the screw;
- clear module extraction arrow/path.

Right panel should show:
- tall/dense neighboring component blocking connector grip;
- screwdriver shaft colliding with an obstruction;
- module extraction path colliding with hardware.

### Required objects and labels

Both panels:

- PCB;
- `Connector`;
- `Replaceable module`;
- `Retention screw`;
- neighboring components/hardware.

Left panel labels:

- `Grip / disconnect access`
- `Screwdriver access`
- `Clear removal path`

Right panel labels:

- `Grip blocked`
- `Tool path blocked`
- `Removal path blocked`
- `Tall / fixed obstruction` where useful.

Optional:
- green check / red X.
- a generic grip/finger-clearance envelope, but keep it schematic rather than anatomical or photorealistic.

### Required technical relationships

- Connector in the good case must have free space where fingers or a tool could plausibly grip/disconnect it.
- Connector in the poor case must be genuinely blocked by nearby hardware, not merely placed closer.
- Screwdriver in the good case must align with the screw axis.
- In the poor case, the screwdriver/tool shaft must physically collide with a neighboring component or enclosure feature before reaching the screw.
- The good-case replacement module must have a real vertical or lateral extraction path.
- The poor-case extraction arrow must visibly intersect an obstruction **after the retention screw is conceptually removed**, so the figure teaches extraction-path access rather than merely fastener access.
- Do not imply all products require field-replaceable board-level parts.
- Do not imply maximum service space is always the design objective.
- Do not show detailed fastener torque, tool size, or enclosure design.

### Spatial / geometry requirements

- Use comparable geometry in both panels. Preserve the same connector, module, screw, and board orientation so the access difference comes from obstruction placement rather than unrelated redesign.
- Keep service features in similar relative positions so the access difference is obvious.
- Provide enough white/board space around arrows and tool paths.
- If using a finger/grip envelope, use simple rounded schematic geometry.
- Make the screw head and screwdriver axis visibly aligned in the good case.
- Make the poor-case collision unmistakable at 900 px.
- Keep module extraction arrow long enough to show a true path rather than just a direction icon.
- Avoid excessive arrows; each service action should have only one primary path.


### Color / style guidance

- Clean engineering-textbook appearance consistent with the current EPAC figure set.
- White or very light neutral background.
- Flat 2D top-view, side-view, or restrained schematic/isometric geometry only where it improves physical understanding.
- Restrained engineering palette:
  - green/blue-green PCB field;
  - copper/gold pads or exposed conductive features;
  - dark gray component bodies;
  - muted blue/gray tools and motion arrows;
  - limited orange/red only for heat exposure or a blocked/problem condition.
- Sans-serif labels sized for the 900 px mdBook render.
- Moderate line weights and consistent visual hierarchy.
- No decorative gradients, glossy rendering, dramatic shadows, logos, watermarks, or branded commercial products.
- Do not rely on color alone; use geometry, labels, line style, arrows, and good/bad structure.
- Do not embed the external figure number, final caption, or an oversized duplicate overall title inside the artwork.


### Scope boundaries

This figure should **not** teach:

- detailed enclosure design;
- fastener torque or screw specification;
- ergonomic-force analysis;
- field-service procedure;
- electrical test access from Section 3.11;
- panelization/fiducials/tooling holes from Section 3.13;
- hot-air thermal exposure from Figure 3.12.2;
- detailed soldering/rework procedure.

### Technical-verification basis

Use as grounding:

- current Sections 3.12.4 and 3.12.5;
- approved outline requirement for connectors, frequently handled/replaced parts, screws, fasteners, and board-retention features;
- DFM principle that physical layout should match the intended maintenance/replacement strategy;
- surrounding-section boundary that detailed product/enclosure design remains outside this section.

No universal connector-grip, screwdriver, or module-extraction clearance dimension should appear.

### Originality / copyright requirements

Create an original generic service-layout comparison.

Do not:

- copy a service-manual illustration;
- trace a commercial product PCB/enclosure;
- reproduce a manufacturer's connector or module geometry;
- use brand-specific screwdriver/fastener artwork.

Use simplified, independently drawn generic geometry.


### Generation guidance

Use a controlled technical-figure workflow.

1. Establish the composition from this specification.
2. If AI image generation is used for an early concept, preserve it only as a concept revision.
3. Once a promising visual baseline exists, freeze the visual language and make only targeted corrections.
4. Rebuild/refine as controlled vector artwork when exact tool paths, heat zones, removal arrows, fastener access, or text placement cannot be controlled reliably in raster generation.
5. Verify every word, arrow, leader, tool/component relationship, and access path after each meaningful revision.
6. Preserve every meaningful revision under a new filename.
7. Do not copy or rename a candidate to the canonical publication filename before explicit project-owner acceptance.



### Editable SVG requirements

The strongest final candidate should include both a publication PNG and a **true editable SVG**.

The SVG must:

- use vector geometry rather than an embedded raster image as the primary artwork;
- keep text editable where practical;
- keep PCB features, components, tools, heat zones, arrows, leaders, fasteners, and labels as separate editable objects;
- define explicit `width`, `height`, and `viewBox` values;
- use `preserveAspectRatio="xMidYMid meet"`;
- include an explicit full-canvas white rectangle as the first visible drawing element, e.g. `<rect x="0" y="0" width="100%" height="100%" fill="#ffffff"/>`;
- preserve adequate safe margins so no tool, arrow, leader, or label is clipped;
- use `markerUnits="userSpaceOnUse"` for normal engineering arrows unless a specific technical reason requires another setting;
- remain clear when rendered at native size and approximately 1600 px, 1200 px, and 900 px width.

Before recommendation, render-check the final SVG at all four sizes.
