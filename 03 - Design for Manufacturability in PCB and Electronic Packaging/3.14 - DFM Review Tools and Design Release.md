# 3.14 - DFM Review, Tools, and Design Release

Sections 3.3 through 3.13 developed design-for-manufacturability decisions at the feature, layout, inspection, rework, and panel level. Before the design is released, those decisions must be checked together.

A useful release question is not simply:

> **Does the PCB editor show zero design-rule violations?**

The broader question is:

> **Is this defined revision manufacturable, assemblable, inspectable, testable, and consistently documented for the selected manufacturing process?**

A practical pre-release logic is:

> **Run configured checks -> perform broader DFM/DFA review -> review supplier findings -> resolve and document findings -> revise and recheck as needed -> confirm release consistency -> release**

---

## 3.14.1 - DRC Is Necessary, but It Is Not the Entire DFM Review

A **design rule check (DRC)** compares the current design against rules that are enabled and configured in the electronic design automation (EDA) system.

Depending on the tool and rule set, DRC may check items such as:

- copper clearance;
- trace width;
- hole and via constraints;
- solder-mask geometry;
- component placement constraints;
- board-edge constraints;
- other electrical or manufacturing rules that have been encoded.

DRC is powerful because it is fast, repeatable, and can run throughout layout.

Its limitation is equally important:

> **DRC can only check rules and relationships that the software has been configured to check.**

A board can therefore have zero reported DRC violations and still have a manufacturability problem.

Examples include:

- the CAD rule set does not match the selected fabricator's actual capability;
- a connector overhang interferes with the intended panel rail;
- an optical inspection path is blocked even though spacing rules pass;
- a rework tool cannot reach a component;
- a local fiducial is needed by the selected assembly process but is not represented by a CAD rule;
- the PCB data are correct but the bill of materials (BOM) and component-placement data describe a different revision.

| Review layer | What it is good at checking | Important limitation |
|---|---|---|
| EDA DRC | Encoded geometric, electrical, placement, mask, and manufacturing constraints | Does not know a requirement that was never encoded or configured |
| Fabrication DFM analysis | Actual manufacturing capability, drill/copper/mask/profile relationships, data completeness | Focuses on the fabricator's process and supplied manufacturing data |
| Assembly DFM/DFA analysis | Placement data, footprints, rotation, clearances, assembly access, BOM/placement consistency | Depends on the assembly data and process information supplied |
| Engineering review | Inspection, test, rework, service, tooling, product intent, tradeoffs, exceptions | Requires engineering judgment and process knowledge |
| Supplier review | Supplier-specific capability, process risk, producibility questions, proposed production adjustments | Findings still require controlled engineering disposition where product intent or released data are affected |

The distinction is not that DRC is "simple" and DFM is always a separate software package. Modern PCB tools can encode many manufacturing rules, and supplier checkers may automate many DFM checks.

The engineering distinction is:

> **Passing an automated rule set is evidence. It is not, by itself, complete manufacturability approval.**

## 3.14.2 - DFM Uses Several Types of Tools and Evidence

The most effective review normally combines several sources of evidence rather than relying on one tool.

A useful question for each review tool is:

> **What does this tool know, what does it actually check, and what important manufacturing information remains outside its rule set?**

### EDA rules and DRC

The PCB editor should contain the approved rules that can be checked directly during design.

Examples include:

- trace/space constraints;
- hole/via constraints;
- board-edge constraints;
- solder-mask rules;
- selected component-placement rules.

A final batch DRC is useful before generating or releasing manufacturing data, but it should use the intended rule set rather than an arbitrary software default.

### Manufacturer rule sets and automated DFM checkers

Fabricators and assemblers may provide:

- capability tables;
- downloadable or recommended CAD rule sets;
- online DFM checkers;
- assembly-data checkers;
- quotation-stage manufacturability analysis.

These tools add knowledge about the **selected process**, but their checks are still limited to the data, process definitions, and rules available to that tool.

For example, a supplier checker may compare:

- measured copper spacing with the chosen fabrication service;
- drilled-hole and annular-ring geometry;
- panel or profile data;
- PCB layout with BOM and component-placement data;
- component rotation and alignment.

### Human engineering review

Some questions remain difficult to reduce to one geometric threshold:

- Can the important solder joints actually be inspected?
- Can the selected test method reach the required nodes?
- Can the component be removed without colliding with neighbors?
- Does the panel provide usable handling and support access?
- Is a supplier-proposed adjustment acceptable for the product?
- Does the complete release package describe one controlled revision?

These are engineering-review questions even when software assists with them.

### Standards and generic guidance

General standards and design guidance can establish useful baselines, but they do not replace:

- the governing product requirement;
- the selected supplier's capability;
- the actual assembly/test process;
- controlled engineering decisions.

For example, a general PCB design standard may provide design context, while a selected supplier's capability defines what that supplier can actually build under the chosen service.

## 3.14.3 - Supplier DFM Findings Are Engineering Inputs

A fabricator or assembler may return a **DFM finding**, question, warning, or proposed production adjustment.

Typical findings may involve:

- a feature outside the selected process capability;
- an ambiguous board outline or layer interpretation;
- a drill/pad/mask relationship that needs clarification;
- a component-placement or rotation conflict;
- a panel, fiducial, tooling, or conveyor concern;
- an assembly-data mismatch;
- a request to confirm whether a process adjustment is allowed.

The correct response is not to treat every supplier message as either "automatically correct" or "only a manufacturing problem."

Engineering should determine what the finding means for the controlled design.

A practical disposition set is:

| Disposition | Meaning | Example action |
|---|---|---|
| **Accept** | The supplier's interpretation or proposed adjustment is acceptable within the controlled manufacturing intent | Document approval and link it to the applicable job/revision |
| **Revise** | The design or released data should change | Update the controlled source, regenerate affected outputs, and recheck |
| **Clarify** | The design intent is correct but the supplied information is incomplete or ambiguous | Add or repair the required controlled information |
| **Deviation / exception** | The design intentionally falls outside a normal rule or preferred process and requires documented authorization | Record scope, rationale, approval, applicable supplier/process, and applicable revision |

A finding should be closed only when its disposition is clear.

Routine manufacturing compensation inside an agreed supplier process is different from an undocumented change to the product definition.

If a supplier proposal changes a controlled product requirement, engineering must review and authorize that change through the organization's normal configuration-control process.

## 3.14.4 - Any Design Change Can Reopen Earlier Checks

A DFM finding often triggers a small change:

- move a component;
- enlarge a mask opening;
- change a via or hole;
- move a fiducial;
- adjust a panel feature;
- correct a component rotation;
- regenerate an assembly file.

A small change can affect more than the original finding.

For example:

- moving a connector may fix panel-rail interference but create a new component-clearance problem;
- changing a footprint may alter solder-mask or courtyard geometry;
- changing a component orientation may require updated placement data and assembly drawings;
- changing a board outline may affect panelization and mechanical fit.

Therefore:

> **Revise -> regenerate affected data -> rerun the relevant checks -> confirm that the original finding is closed without creating a new one.**

Rechecking is part of the engineering change, not optional cleanup.

---

## 3.14.5 - Release Consistency Matters as Much as Individual File Correctness

A manufacturing package may contain several kinds of information.

At awareness level, these may include:

- fabrication data;
- drill/profile information;
- assembly data;
- bill of materials (BOM);
- centroid, pick-and-place, or component-placement-list data;
- paste or stencil data where separately supplied;
- fabrication and assembly drawings or notes;
- part numbers and revision identifiers.

Not every organization uses the same file set or data format.

The important DFM/release principle is:

> **All applicable released information must describe the same approved product definition and revision.**

A package can contain individually valid files and still be wrong as a package.

Examples:

- PCB copper data are from Revision C, but the BOM is from Revision B;
- the footprint was rotated in the PCB layout, but old pick-and-place rotation data were sent;
- a board outline was changed, but an old assembly drawing still shows the previous geometry;
- panelization changed, but component-placement coordinates were not regenerated.

- verify the revision identity of the package before release.

## 3.14.6 - Applied Example: Zero DRC Violations, but Not Ready for Release

Assume a small mixed-technology PCB reports **zero DRC violations** in the PCB editor.

During pre-release review, three additional issues are found:

1. a connector body extends into the intended panel handling rail;
2. the selected assembler requests a local fiducial near a precision-placement region;
3. the component-placement file still contains the old rotation for one polarized component.

The DRC result is not false.

It simply does not prove that these three broader release conditions are acceptable.

A suitable response is:

| Finding | Why DRC may not catch it | Engineering response |
|---|---|---|
| Connector interferes with panel rail | Panel/conveyor geometry may not be encoded in the CAD rule set | Revise the layout or panel strategy, then recheck |
| Local fiducial requested | Requirement may be specific to the selected assembly process | Confirm the assembler's need; add or formally resolve the requirement |
| Placement rotation is outdated | The PCB geometry may be correct while exported assembly data are stale | Regenerate placement data from the controlled revision and verify it |

The design is ready for release only after the findings are resolved, affected outputs are regenerated from the controlled design source, and the complete package is synchronized to the approved revision.

## 3.14.7 - A Practical Design-Release Sequence

A compact release sequence is:

> **1. Run configured DRC and other automated checks**  
> **2. Perform broader DFM/DFA review**  
> **3. Review fabricator and assembler findings**  
> **4. Disposition each finding**  
> **5. Revise the controlled design and affected data as required**  
> **6. Rerun the relevant checks**  
> **7. Confirm that all release artifacts describe the same approved revision**  
> **8. Release the controlled package**

Different organizations may use different gates, software, forms, or approval roles.

The engineering intent remains the same:

> **Do not release until the design, the manufacturing review, the supplier responses, and the released information agree on what is being built.**

---

## Section Takeaway

The main ideas from this section are:

- DRC checks configured rules and is an essential automated design tool;
- zero DRC violations do not by themselves prove manufacturability;
- broader DFM review includes supplier capability, assembly, inspection/test, rework, tooling/panelization, cost/yield tradeoffs, and documentation consistency;
- manufacturer rule sets, automated DFM tools, supplier review reports, and engineering judgment provide different kinds of evidence;
- supplier findings require controlled disposition rather than undocumented assumptions;
- any design change should trigger regeneration and rechecking of affected outputs;
- individually correct files can still form an incorrect release package if they describe different revisions;
- release is a controlled engineering gate, not a guarantee that no future manufacturing learning will occur.
